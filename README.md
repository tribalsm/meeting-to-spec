# Meeting to Spec

Pet-проект, созданный после хакатона 2026. Сервис превращает запись встречи в черновик технического задания: распознаёт речь, выделяет требования и помогает проверить результат перед экспортом в Markdown.

## Проблема и решение

После встречи договорённости часто остаются в записи, заметках или памяти участников. На расшифровку, выделение требований и подготовку первого черновика ТЗ уходит много времени, а важные ограничения и открытые вопросы легко потерять.

Meeting to Spec принимает аудио- или видеозапись, строит транскрипцию с таймкодами и формирует структурированный черновик ТЗ. Пользователь может найти нужный фрагмент разговора, проверить связь требования с источником, отредактировать результат и скачать его в Markdown.

## Основной сценарий

1. Пользователь загружает запись встречи в MP3, MP4, WAV, M4A или WebM.
2. Интерфейс показывает запись в плеере до запуска анализа.
3. Backend получает файл, проверяет формат и размер, затем отправляет запись на распознавание речи.
4. Сервис возвращает транскрипцию с таймкодами и сформированное ТЗ.
5. Пользователь ищет фрагменты транскрипции, проверяет и редактирует требования.
6. Готовое ТЗ скачивается в формате Markdown.

## Возможности

- загрузка аудио и видео до 25 МиБ;
- просмотр и прослушивание записи перед анализом: воспроизведение, перемотка, скорость и громкость;
- транскрипция на русском языке с временными сегментами;
- извлечение summary, ролей, требований и пользовательских сценариев;
- отдельные категории: ограничения, условия, открытые вопросы, договорённости и противоречия;
- поиск по транскрипции и переход к совпадениям;
- связь требований и сценариев с исходными сегментами разговора;
- добавление, редактирование и удаление требований;
- экспорт результата в Markdown;
- обработка ошибок формата, размера файла и временной недоступности внешнего AI-сервиса.

## Архитектура

```text
React + Vite
    |
    | POST /api/analyze, multipart/form-data: file
    v
FastAPI
    |
    +-> проверка формата и размера, временный файл
    +-> Groq Whisper Large V3 Turbo
    |       |
    |       v
    |   транскрипция + сегменты с таймкодами
    +-> GPT-OSS 120B: основная структура ТЗ
    +-> GPT-OSS 20B: дополнительные аналитические категории
    |
    v
нормализация и merge без дублей
    |
    v
единый JSON-ответ для frontend
```

HTTP API остаётся компактным:

- `GET /health` возвращает состояние backend;
- `POST /api/analyze` принимает поле `file` в `multipart/form-data` и возвращает транскрипцию и анализ.

Подробное описание API и кодов ошибок находится в [backend/README.md](backend/README.md).

## AI pipeline

```text
Запись
  -> Whisper Large V3 Turbo
  -> транскрипция с таймкодами
  -> GPT-OSS 120B
  -> GPT-OSS 20B
  -> merge и нормализация
  -> единый JSON
  -> интерфейс и Markdown-экспорт
```

### Зачем два LLM-прохода

Основной проход использует `openai/gpt-oss-120b`. Он получает транскрипцию, при необходимости разбитую на фрагменты, и формирует основную структуру: summary, роли, requirements и userScenarios.

После него запускается специализированный проход `openai/gpt-oss-20b` по той же транскрипции. Он извлекает только constraints, conditions, openQuestions, agreements и contradictions. Узкий prompt повышает шанс не потерять информацию вроде «пока не решили», «отдельно согласуем» или «для первой версии не делаем».

Результат второго прохода нормализуется и объединяется с основным без дублей. Если дополнительный запрос к Groq временно не выполнился, пользователь всё равно получает результат основного анализа. Это не меняет контракт API.

## Локальный запуск

Требования: Python 3.11+ и Node.js 22+. Нужен ключ Groq API.

### 1. Backend

В первом окне PowerShell:

```powershell
Set-Location backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `backend/.env` и заполните только значение `GROQ_API_KEY`. Файл `.env` не должен попадать в Git.

Запустите backend:

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Проверка: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health).

### 2. Frontend

Во втором окне PowerShell из корня репозитория:

```powershell
Set-Location frontend
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). В режиме разработки Vite проксирует `/api` и `/health` на `127.0.0.1:8000`, поэтому `frontend/.env` для локального запуска не нужен.

Для опубликованной сборки укажите публичный адрес backend в `VITE_API_URL`. Эта переменная доступна браузеру, поэтому в ней нельзя хранить API-ключи.

## Ограничения MVP

- Качество результата зависит от качества звука и точности моделей.
- Внешний Groq API может быть временно недоступен или ограничивать частоту запросов.
- Один файл ограничен 25 МиБ, а длинная транскрипция анализируется максимум в восьми фрагментах.
- Результат является черновиком и требует проверки человеком.
- Ручные изменения живут в состоянии страницы до её обновления. Для сохранения используйте Markdown-экспорт.
- Нет авторизации, базы данных, истории встреч и совместного редактирования.

## Возможное развитие

- хранение записей, транскрипций и версий ТЗ;
- авторизация и совместная работа над требованиями;
- асинхронная очередь для длинных записей и отображение прогресса по этапам;
- поддержка нескольких языков и идентификация спикеров;
- экспорт в DOCX, Jira, YouTrack и другие системы;
- настройка шаблонов ТЗ и доменных словарей;
- оценка качества извлечения требований на размеченных встречах.

## Использование AI-инструментов при разработке

AI-инструменты использовались как помощники при проектировании структуры, формулировке промптов, написании тестов, проверке интеграции и подготовке документации. Решения по архитектуре, контракту API, проверкам и итоговым изменениям проверялись в репозитории человеком. API-ключи не передаются во frontend, а записи пользователей не хранятся в Git.

## Конфиденциальность

Загруженная запись передаётся в Groq для распознавания и анализа. Не загружайте конфиденциальные материалы без предварительной оценки условий использования внешнего провайдера и требований вашей организации.
